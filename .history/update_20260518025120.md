# Chunk 链路 Edge Predict 异步通信改造设计

## 目标与边界

`backends/chunk` 是当前统一库后续演进的主链路。改造目标是在 chunk 链路下同时支持 CTDG 采样式 edge predict 和 DTDG 全图/快照式 edge predict，并把数据放置、索引构建、通信路由、异步通信、异步梯度同步、模型和 task head 接口统一到一套可调度的 `ExecutionUnit + CommPlanBundle` 设计里。

本设计保留现有代码的方向：

- `starry_unigraph/backends/chunk/data/partition.py` 继续作为 chunk-native `PartitionData`。
- `starry_unigraph/backends/chunk/data/route.py` 继续承载 `SpatialRouteData`、`MemoryRouteData`。
- `starry_unigraph/backends/chunk/data/comm.py` 扩展为统一异步通信管理器。
- `starry_unigraph/backends/chunk/data/propagation_route.py` 继续参考 FlareDTDG 的 autograd all-to-all route，用于 DTDG/全图 edge predict 层通信。
- `starry_unigraph/backends/chunk/runtime/event_engine.py` 继续吸收 MemShare native temporal sampler，用于 CTDG 事件采样链路。

设计边界：

- 负样本采样在线执行，不在 prepare 阶段预生成。
- train 和 test 允许不同负采样分布。train 降低非本分区 dst 比例；test 使用全军平均/global dst 分布。
- CTDG 在通信阶段由采样器把 event 及相关子图拉取到本地；DTDG 在 edge predict/head 或 GNN propagation 层通信。
- edge predict 通信必须异步，至少支持 feature fetch、memory/state sync、propagation、grad sync 四类通道并发。

## 核心放置策略

### 节点与热点

prepare 阶段构建以下全局表，并写入 `placement.pth`：

- `node_to_chunk: [num_nodes]`，节点所属 chunk/cluster。
- `node_owner: [num_nodes]`，当前负责该节点 cold state、feature、memory 的 rank。
- `node_master: [num_nodes]`，热点节点主副本所在 rank，作为一致性写入点。
- `replica_mask: [num_nodes]`，是否为热点节点。
- `hot_replica_ranks` 或压缩 CSR，记录热点节点在哪些 rank 有副本。
- `placement_version`，每次 trial 级别 rebalance 后递增。

### Edge Predict 事件分配

对于正样本 event `(src, dst, ts, eid)`：

```text
src_hot = replica_mask[src]
dst_hot = replica_mask[dst]

if src_hot xor dst_hot:
    event_owner = owner(non_hot_node)
elif not src_hot and not dst_hot:
    event_owner = owner(dst)       # 默认 dst-cut，兼容当前 dst_chunk 连续存储
else:
    event_owner = owner(dst)       # 双热点时按 dst master，必要时用负载最小 rank 打破平局
```

这样能把“热点数据和非热点数据的连边”分配到非热点所在分区，减少热点副本的一致性压力。`PartitionData.dst_chunk` 仍按目标 chunk 排序，保证同一个目标 chunk 的 event 在存储上连续。

## 分区算法支持

chunk 链路需要支持三类分区入口：

- `speed_ctdg`：复用 CTDG SPEED / MemShare 的事件流分区思想，适合 TGN/JODIE/APAN 等。
- `metis_dtdg`：复用 FlareDTDG 对快照图的 node partition 和 route 构建，适合 EvolveGCN/MPNN-LSTM/TGCN。
- `hot_aware_edge_predict`：新增默认策略，在基础 node partition 之上按热点和 edge predict 事件 owner 规则重写 event placement。

prepare 输出分两层：

- Phase 1，图和事件无关放置：`node_to_chunk`、`node_owner`、热点副本、chunk load estimate。
- Phase 2，任务相关放置：edge predict 的 `event_owner`、负采样 dst pool、CTDG sample root 分配、DTDG propagation route。

rebalance 只允许在 epoch/trial 边界发生，不在 step 内改变 placement。重分区时复用 `MemoryRouteData` 的 Phase 1 `unique_nodes/cand_pos`，只重建 owner 相关 ptr 和 route，避免重跑 expensive temporal dedup。

## 索引构建策略

### Canonical Event Store

全局 event 以列式 tensor 保存：

- `event_src`
- `event_dst`
- `event_ts`
- `event_eid`
- `event_owner`
- `event_dst_chunk`
- `event_split`

每个 rank 的 `PartitionData` 只保存本 rank event_owner 对应事件，以及该 rank 计算需要的 remote src/dst 边界节点。当前 `snapshot_to_partitiondata_tensors()` 中“按 `dst_chunk * num_nodes + dst` 排序”的原则保留，但排序键扩展为：

```text
(time_slice, event_owner, dst_chunk, dst, ts, eid)
```

### CTDG Temporal Index

CTDG 使用 `ChunkGraphStore.temporal_index_view()` 暴露给 `MemShareEventEngine`：

- 全局或本地 CSC/CSR temporal adjacency。
- `edge_ids` 指回 canonical event store。
- `timestamps` 保持 int64 contiguous。
- `PlacementView` 内含 `node_owner/node_master/replica_mask`。

CTDG batch roots 包括：

- 正样本 `pos_src/pos_dst` 的两端节点。
- 在线负采样生成的 `neg_dst`，以及对应 `neg_src=pos_src`。
- memory 需要读写的节点集合 `src ∪ dst ∪ neg_dst`。

采样后，MFG 构建必须产出 `input_nodes/output_nodes/edge_ids/node_ts`，并附带远端节点清单，用于异步 feature/memory fetch。

### DTDG Snapshot Index

DTDG 保持 FlareDTDG 的 per-snapshot route 思路：

- 每个快照/窗口构建本 rank local dst 节点。
- 远端 src 追加在 local dst 后面。
- `send_index/send_sizes/recv_sizes` 用于 edge predict head 或 GNN layer 里的 activation propagation。

`ChunkPropagationRoute` 是当前 chunk-local 版本，后续需要补齐 Flare 的两个语义：

- forward 返回 `cat([local_x, recv_x])`，方便 DTDG block 直接索引 remote src embedding。
- backward 通过 all-to-all 把 remote grad 返回 owner，并对 `send_index` 做 `index_add_`。

当前实现只返回 recv buffer；需要加一个兼容模式：

```text
append_recv=True  -> return cat([x, recv])
append_recv=False -> return recv
```

DTDG edge predict head 在 `append_recv=True` 的 embedding 表上计算 pos/neg score。

## 负样本采样策略

新增 `EdgePredictNegativeSampler`，配置项：

```yaml
sampler:
  neg_strategy: edge_predict_mixed
  neg_ratio: 1
  train_remote_dst_prob: 0.15
  test_policy: global_average
  dst_pool: global_dst
```

### Train

train 阶段目标是减少非本分区 dst 比例，但不完全退化成 local negative：

```text
with probability 1 - train_remote_dst_prob:
    neg_dst ~ local_dst_pool[rank]
else:
    neg_dst ~ global_dst_pool
```

若正样本 dst 本身是 remote 或热点副本节点，`train_remote_dst_prob` 可以按 batch remote ratio 动态调高，避免 train/test 分布差距过大。

需要记录 importance weight，用于修正 biased negative distribution：

```text
neg_weight = p_test(neg_dst) / p_train(neg_dst)
```

第一版可只输出权重字段但默认不启用 loss reweight；后续在评估偏差明显时打开。

### Test / Val

test 阶段使用全军平均 dst 采样：

- 每个 rank 按相同 seed 生成候选 dst。
- `global_dst_pool` 按所有 rank 的 dst 去重或按事件频率加权。
- 每个 rank 负责自己的正样本，但负样本 dst 分布一致。

为降低通信复杂度，test 负采样仍在线执行，但 dst pool 在 prepare 或 epoch start 时 all-gather 一次，形成只读 CPU/GPU tensor。

## 通信路由构建

### 路由类型

统一使用 `CommPlanBundle`，扩展为四类通道：

- `fetch`：CTDG sampled MFG 的 feature/memory read，或 DTDG 需要的 remote feature read。
- `propagation`：DTDG full graph / edge predict layer 的 autograd all-to-all。
- `state_sync`：TGN/APAN/JODIE memory/mailbox 写回 owner 和热点副本。
- `grad_sync`：异步梯度同步和参数备份一致性。

### CTDG 路由

CTDG 路由由采样结果驱动：

1. sampler 输出 `remote_node_ids`。
2. 根据 `node_owner[remote_node_ids]` 排序，生成 `send_ptr/recv_ptr/recv_node_ids`。
3. `CommPipeline.submit_spatial()` 异步拉取 feature。
4. `CommPipeline.submit_memory()` 异步拉取 memory/mailbox，计算完成后再 submit writeback。

为了减少每 batch 动态建路由开销，使用两级缓存：

- key = `(placement_version, block_id, sampled_remote_hash)` 的 exact cache。
- key = `(placement_version, time_slice, dst_chunk)` 的粗粒度 route template。

### DTDG 路由

DTDG 路由由快照 edge index 和 node partition 预构建：

1. 对每个 rank 取 `dst_ids = nodes[node_owner == rank]`。
2. 找所有边中 `dst in dst_ids` 的 `src`。
3. remote src 按 owner 排序形成 `recv_node_ids`。
4. 反向整理本 rank 需要发送给各 peer 的 local node index，形成 `send_index/send_sizes`。
5. 保存为 `ChunkPropagationRoute` 或 `SpatialRouteData + PropagationPlan`。

edge predict 的负样本路由不能完全预构建，因为 neg_dst 在线生成。处理方式：

- train：优先 local neg_dst，少量 remote neg_dst 走动态 fetch route。
- test：global_average 负样本可能 remote 比例高，按 test batch 动态构建 `neg_fetch_route`，并异步 overlap。

## 异步通信管理

`CommPipeline` 从三通道扩展为事件化调度器：

```text
submit_fetch(plan, tensors)      -> CommHandle
submit_propagation(route, x)     -> RouteHandle
submit_state_sync(plan, state)   -> CommHandle
submit_grad_sync(bucket)         -> GradHandle
await(handle)                    -> result
drain(channel=None)
```

每个 handle 记录：

- `block_id`
- `placement_version`
- `channel`
- `cuda_stream`
- `dist.Work` 列表
- recv buffers
- dependency handles

推荐三条 CUDA stream：

- `compute_stream`
- `fetch_stream`
- `comm_stream`

step 调度采用一拍或两拍流水：

```text
prefetch batch[t+1] feature/memory
compute  batch[t]
submit   batch[t] state writeback and grad sync
await    batch[t+1] only when model needs remote data
```

CTDG 可把 sample 放在 CPU worker/native sampler 线程，feature/memory all-to-all 在 GPU stream 上异步执行。MemShare 的 `DistributedDataLoader` 做法是 submit sampling future，再在下一次迭代等待 feature all-to-all；chunk 链路应把这个逻辑下沉到 `CommPipeline + EventEngine`，避免 dataloader 热循环里散落通信细节。

DTDG model layer 内通信参考 FlareDTDG：

- `send()` 创建 autograd key，启动 `all_to_all_single(async_op=True)`。
- coroutine `await asyncio.sleep(0.0)` 把控制权交还 layerwise scheduler。
- `recv()` 在真正需要 remote tensor 时 wait。
- backward 反向 all-to-all，把 remote gradient 回传 local owner。

## 异步梯度同步与权重备份

### 参数同步策略

提供两种模式：

- `ddp_sync`：标准 DDP bucket all-reduce，作为 correctness baseline。
- `async_stale`：异步梯度同步，允许最多 `staleness <= K` 的权重延迟。

edge predict 异步通信要求推荐先落地 `async_stale`，但默认 `K=1`：

```yaml
runtime:
  grad_sync:
    mode: async_stale
    max_staleness: 1
    bucket_cap_mb: 25
    backup_slots: 2
```

### 权重备份

每个 rank 维护 `WeightVersionManager`：

- `active_version`：当前 forward 使用的参数版本。
- `backup_slots`：环形保存最近 K+1 个参数快照。
- `grad_bucket.version`：bucket 对应的 forward 权重版本。
- `optimizer_apply_version`：optimizer 正在应用的版本。

流程：

1. step 开始前保存 `model.state_dict()` 或 flat parameter buffer 到 slot `v`。
2. forward/backward 使用 version `v`。
3. backward hook 将梯度写入 `GradBucket(v)`。
4. bucket 满后启动 `all_reduce(async_op=True)`。
5. 若 step `v+1` 需要继续 forward，不等待 `v` 的 grad sync，直接使用本地 optimistic weight。
6. 当 `GradBucket(v)` 完成，检查当前参数与 backup slot `v` 的差异：
   - `K=1` 简化方案：在 apply 前等待上一个 bucket 完成，保证 optimizer 顺序一致。
   - 高级方案：用 backup slot `v` 临时恢复参数，apply synced grad，得到 `v+1`，再把 pending local update rebase 到当前版本。

第一版建议实现 `ordered_async`：

- forward 可以和上一个 all-reduce overlap。
- optimizer step 必须按版本顺序 apply。
- 不做复杂 rebase。

这样实现简单，仍能 overlap backward 后段、下一 batch prepare/fetch 与 grad all-reduce。

### 非参数状态

TGN/APAN memory/mailbox 不是模型参数，不进入 grad all-reduce。它们走 `state_sync`：

- owner-write：冷节点只写 owner。
- hot-replica：热点先写 master，再异步 fanout 到 replica。
- timestamp reduce：同一节点多更新按最大 ts 取最新，参考 MemShare `scatter_max(ts)` 语义。

## Train Step

### CTDG Edge Predict Train

```text
for unit in loader.iter_train_units():
    # 1. event batch
    view = unit.payload  # EventView

    # 2. 在线负采样，train 使用 local-biased dst
    neg = neg_sampler.sample(split="train", owner_rank=rank, dst_pool=...)

    # 3. temporal sampler 拉 event 相关子图
    sample_handle = event_engine.submit_sample(view, pos_edges, neg_edges)

    # 4. 根据 sampled remote nodes 提交异步 feature/memory fetch
    fetch_handle = comm.submit_fetch(unit.comm_plan.fetch)

    # 5. await 远端数据，仅在 MFG materialize 前同步
    sampled = sample_handle.result()
    remote = await fetch_handle
    batch = materialize(sampled, remote, neg)

    # 6. model forward + edge head
    out = model(batch)
    loss = edge_predict_loss(out, batch, neg_weight=batch.neg_weight)

    # 7. backward，本地梯度进入 GradBucket
    loss.backward()

    # 8. memory/mailbox update，异步写回 owner/master/replica
    state = memory_updater(...)
    comm.submit_state_sync(unit.comm_plan.state_sync, state)

    # 9. 参数 grad bucket 异步 all-reduce，ordered async optimizer
    grad_sync.maybe_submit()
    grad_sync.maybe_apply_ready(optimizer)
```

关键约束：

- 对同一个节点 memory，写回必须按 ts 单调；晚到的旧 ts 丢弃。
- event_owner 只决定谁计算 loss；memory owner/master 决定谁接收状态更新。
- batch 内负样本如果引入 remote dst，必须加入 feature/memory fetch plan。

### DTDG Edge Predict Train

```text
for snapshot in loader.iter_train_units():
    # 1. 载入本 rank snapshot block
    block = snapshot.payload

    # 2. local-biased negative sampling
    neg = neg_sampler.sample(split="train", ...)

    # 3. GNN/edge head 内通过 ChunkPropagationRoute 异步拿 remote src embedding
    h = model.encode(block)  # route.async_forward inside layer

    # 4. edge predict head 对 pos/neg 打分
    out = edge_head(h, pos_edges, neg_edges, route=optional_neg_route)

    # 5. backward 触发 route backward all-to-all，把 remote grad 回传 owner
    loss.backward()

    # 6. grad_sync ordered async
    grad_sync.maybe_submit()
    grad_sync.maybe_apply_ready(optimizer)
```

DTDG 的通信主要在 propagation route 的 autograd function 内，外层只负责给每层 route 绑定 process group 和 stream。

## Test / Eval Step

test 不更新参数和 memory，但要保持负采样全军平均：

```text
for unit in loader.iter_eval_units(split="test"):
    neg = neg_sampler.sample(split="test", policy="global_average")
    build dynamic neg_fetch_route if needed
    await feature/memory fetch
    with torch.no_grad():
        out = model(batch)
        metrics.update(pos_score, neg_score)
```

CTDG test 可选择是否冻结 memory：

- transductive temporal evaluation：按时间推进 memory，但不反传、不更新参数。
- static evaluation：完全冻结 memory，所有 batch 使用 checkpoint memory。

配置项：

```yaml
eval:
  memory_policy: temporal_replay   # temporal_replay | frozen
  negative_policy: global_average
```

## Model 支持

统一模型接口：

```python
class ChunkModel(nn.Module):
    def encode(self, batch_or_unit) -> NodeEmbeddingTable:
        ...

    def forward(self, batch_or_unit) -> dict:
        emb = self.encode(batch_or_unit)
        return self.task_head(emb, batch_or_unit)
```

CTDG 模型族：

- TGN
- JODIE
- DyRep
- APAN

需要 memory/mailbox hooks：

- `prepare_memory(input_nodes, ts)`
- `update_memory(pos_edges, embeddings, ts)`
- `state_dict_nonparam()` / `load_state_dict_nonparam()` 用于 checkpoint memory。

DTDG 模型族：

- GCN
- TGCN
- EvolveGCN
- MPNN-LSTM

需要 route-aware layer：

- layer 接收 `ChunkPropagationRoute` 或从 block 上读取 `block.route`。
- 支持 `async_forward()`，让多层/多快照 route 通信 overlap。

## Task Header 支持

新增 chunk-native task head，不再直接使用 global id 索引 embedding。原因是 distributed batch 的 embedding 表通常是 local compact table。

接口：

```python
class ChunkEdgePredictHead(nn.Module):
    def forward(
        self,
        embeddings,
        pos_src,
        pos_dst,
        neg_src,
        neg_dst,
        id_map=None,
        pair_owner=None,
    ) -> dict:
        ...
```

要求：

- `id_map` 将 global node id 映射到 batch-local row。
- 若 `embeddings` 已是 global table，`id_map=None`。
- 支持 scorer：
  - dot product
  - bilinear
  - MLP on `[h_src, h_dst, h_src * h_dst, edge_feat]`
- 输出：
  - `pos_score`
  - `neg_score`
  - `pos_edge_id`
  - `neg_dst`

loss 由 task adapter 负责：

- BCE 默认。
- 可选 sampled negative importance weight。
- metrics 支持 AUC/AP/MRR/Hits@K。

## 与参考项目的映射

### FlareDTDG

采纳：

- `Route.from_graph()` 的 route 构建思想。
- autograd `send/recv` 拆分，forward all-to-all 与 backward all-to-all 对称。
- `AsyncModule.layerwise()` 的 coroutine 调度，使多层图卷积通信延后到需要时 wait。
- STGraphLoader 的 chunk order/chunk decay 思路，用于 DTDG snapshot/chunk 训练的局部化和负载调度。

需要调整：

- route 返回值要同时支持 append local + remote，满足 edge predict pair indexing。
- route 对象要落到 `backends/chunk`，不依赖 Flare 包。

### MemShare-public

采纳：

- native temporal sampler 只绑定一次，batch 循环只传 contiguous tensor。
- 在线负采样，train 可按本地/远端比例倾斜，test 使用全局分布。
- feature/memory/mailbox all-to-all 使用 async work handle，下一拍等待。
- memory/mailbox 更新按 timestamp reduce，重复节点只保留最新更新。
- hot/shared node 可用 historical cache 或 replica fanout 降低远端访问。

需要调整：

- 通信逻辑从 dataloader 中抽出，放入 `CommPipeline`。
- `DistIndex/DistributedTensor` 的能力用 chunk 自己的 `PlacementView + RouteData` 表达，减少旧库耦合。

## 实现拆分

1. 扩展 placement/artifact schema：补齐 `event_owner`、hot replica、dst pools、manifest 字段。
2. 实现 `EdgePredictNegativeSampler`：train local-biased，test global_average，输出可选 `neg_weight`。
3. 扩展 `BatchData`：加入 `id_map`、`neg_weight`、`remote_node_ids`、`route_handles`。
4. 扩展 `CommPlanBundle`：加入 `grad_sync`，并让 fetch/state/propagation 支持动态 route。
5. 改造 `CommPipeline`：handle 化、stream 化、支持 prefetch/await/drain。
6. 修正 `ChunkPropagationRoute`：支持 append local+remote，保持 autograd backward route。
7. 新增 `ChunkEdgePredictHead`：batch-local id_map 打分，不直接假设 global embedding table。
8. 改造 CTDG train/eval step：sample -> async fetch -> materialize -> forward -> async state sync。
9. 改造 DTDG train/eval step：route-aware encode/head，backward 自动同步 remote activation grad。
10. 新增 `WeightVersionManager` 和 `AsyncGradSynchronizer`：先实现 ordered async，后续再扩展 bounded stale rebase。
11. 增加 tests：
    - event_owner 热点/非热点分配。
    - train/test 负采样分布。
    - route send/recv shape 和 backward gradient。
    - async state sync timestamp reduce。
    - single-rank 与 multi-rank 行为一致性。

## Correctness 约束

- `placement_version` 不匹配时禁止复用 route/cache。
- 同一节点 memory 写回以最大 timestamp 为准。
- online negative sampling 的 seed 需要由 `(epoch, split, rank, global_step)` 决定，test 阶段所有 rank 的 global dst 分布一致。
- async grad apply 必须按 version 顺序进入 optimizer。
- checkpoint 必须同时保存：
  - model weights
  - optimizer state
  - `WeightVersionManager` 当前 version
  - memory/mailbox state
  - placement manifest

## 性能目标

- CTDG：sampling、feature/memory fetch、上一 batch state sync、当前 batch compute 至少两两 overlap。
- DTDG：propagation route forward/backward 使用 autograd all-to-all，不在 Python 层同步每层通信。
- 负样本 train remote dst 比例可控，默认显著低于全局采样，test 保持全局一致。
- rebalance 后只重建 route Phase 2，不重建 temporal dedup 和 canonical event store。
